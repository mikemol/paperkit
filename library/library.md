# The Paperkit Concept Library

*Each concept's witness is authored and GRADED here once; every view imports the certificate (verdict + engine fingerprint) rather than re-authoring a parallel proof.*

## Adequacy: The Δ Falsifiability Concept

The adequacy witness runs the real grader over a fixture, so mutating an engine def-site flips it — the certificate's sensitivity fingerprint IS the engine, which every importing view inherits [@adequacy-pitch]; the same witness under the deep key certifies the grade ladder — a presupposed file grades vacuous, a content-sensitive command behavioral — so the paper's deep exposition imports the identical proof the pitch does [@grade-ladder].

## Delta: The Grader and Coherence

Δ flags the relevance gap without closing it — a check can grade behavioral while sensitive only to inputs other than the document's content, and content-sensitivity marks the difference, so behavioral is necessary but not sufficient for relevance [@crash-sensitive-limit]. One grade sits outside the falsifiability ladder — a verdict-import is graded imported, its adequacy delegated to a sibling the gate verifies on its own, run once and never mutation-swept [@imported-grade]. The sweep runs in a sandbox copy whose mutation surface excludes sibling projects (a nested directory with its own paper.toml), so each project grades independently of the others [@sandbox-grade]. Definition resolution turns each claim's sensitivity into an engine-capability fingerprint and checks declared grounding against it — a rests-on edge whose fingerprint overlaps its premise's is reflected, a disjoint one from a claim that tests engine capability is a genuine miss, and one from a claim that tests nothing engine is vacuously discharged [@grounding-reflected]; and stricter, emergence is the coverage sibling of grounding — grounding asks whether a rests-on edge overlaps its premise's fingerprint, emergence whether a claim's whole fingerprint is covered by its premises', so a claim that adds no engine sensitivity beyond its grounding collapses while any residual is its irreducible increment [@emergence-collapse]. Rests-on is a separate grounding edge — a claim's effective grade is clamped to the weakest grade along it, regardless of prose order [@edge-rests-grounds]. A verdict is reusable exactly when nothing the check can REACH has changed, so the cache key is the check's slice — its witness, the transitive closure of every top-level body it names, and the content of every module that closure reaches; a slice that reads only function bodies stops at a constant's own name and one that reads only names never leaves the file, and each omission serves a stale pass [@slice-cache].

## Model: A Claim Is a Record

A claim is one bibliography entry — a statement, its rubric section, its dependencies, and its check — parsed by the engine's OWN bib reader, so mutating a parser def-site flips the witness and the certificate's fingerprint IS that parser [@rm-model]; the same witness under the paper's key certifies that a claim is a single record — the deep view imports the identical proof the README pitch does [@claim-is-record].

## Resolver: The Verifier and the Escape Hatch

Each claim carries a machine-checkable verifier — the check field names a verb and the gate RESOLVES it; the parser and the resolver are engine, so the certificate's fingerprint is them [@rm-verifier]; the same witness under the paper's key certifies that each claim bears a machine-checkable verifier [@claim-bears-check]; cmd is the escape hatch every check reduces to, and a new domain adds a verifier in config without touching the engine — a config-supplied type resolves, an unregistered one does not [@rm-resolver-cmd]; the paper's cmd-escape face imports this same certificate — cmd is the universal escape hatch every other check reduces to [@cmd-escape]; and the paper's new-domain-adds face too — supporting a new domain means adding verifiers, not editing the engine [@new-domain-adds]; the resolver component's certificate — a verifier is named type:target, EVERY declared verb dispatches to a real branch (read from resolver.VERBS, nothing re-listed), the built-in set is closed, and a custom type dispatches through the registry [@rm-resolver]; the paper's verifier-named face imports this certificate — the type prefix selects the verb [@verifier-named]; and its gate-dispatches face — the gate dispatches through a small registry of check types, built-in and custom [@gate-dispatches]; and its two-builtins face — a verifier ships built in per verb, and the set is pinned ENUMERATIVELY rather than by count, closing the adequacy gap that let a fifth verb falsify the prose silently [@two-builtins]; and a concept key is GRADED — family, optional subfamily, argument — and one depth-agnostic walk resolves every grade, so a flat key is the degenerate case rather than a separate mechanism, while two keys differing only in argument share one implementation yet stay distinct witnesses to the gate [@graded-key]; the concept verb IMPORTS rather than runs — the engine's own registry types it as a boundary-crossing import, and a citation grades `imported`, its adequacy delegated to the library that graded it once [@concept-builtin]; a library is a HASH-CONS table — two keys naming one concept resolve to the SAME canonical witness object rather than to copies that could drift, and a singly-cited concept is canonical too, so interning is a property of being a concept and not a reward for repetition [@concept-interned]; one truth carries SEVERAL prose faces — measured against the live corpus, a shared key is cited from more than one project, so distinct views state a concept in their own register while importing the identical proof [@concept-views]; the seam resolves CONSUMER-FIRST with per-key fallthrough — a project's own library answers a key it owns, a key it disclaims falls through to the engine's, and directory-level selection alone would make every engine concept unreachable from any repository owning a library [@concept-shareable].

## Gate: Enforcing the Invariants

An unverified sentence cannot ship — a claim whose check FAILS blocks the gate; the gate is engine, so its def-sites are the fingerprint [@rm-noship]; the paper's fail-omits face imports this same certificate — a claim whose verifier fails simply does not appear in the prose [@fail-omits]; the gate ENFORCES its invariants — the committed prose equals its projection, and every cited claim's check passes — so violating each makes it RED [@rm-cmds-inv]; the paper's self-host face imports this same certificate — the gate that accepts the paper is the very subject it describes, enforcing the invariants the paper states [@gate-is-subject]; the gate is blind to RELEVANCE — a passing check proves a sentence NAMED a verifier, not that the verifier ENTAILS the claim, so a false sentence with a behavioral yet irrelevant check still passes: verification here is adequacy, not proof of meaning [@adequacy-gap]; a tool's behavioural BOUNDARY is a triple and not a happy path — a minimal input that PASSES, a minimal input that FLAGS, and the minimum DELTA between them, so the documented edge is the one the tool actually has; a tool shown only passing has an undefined boundary, since nothing distinguishes a check that discriminates from one that cannot fail, and the delta is what makes the pair a MEASUREMENT rather than two anecdotes [@boundary-is-a-triple].

## Projector: The Document Is the Projection

The projector component's certificate — a document IS the projection of its claim-DAG: the title, every rubric section, and every claim's prose appear in the emitted document, which leads with a heading [@rm-pitch]; the paper's thesis face imports this certificate — a scholarly paper as the projection of a claim-DAG [@paper-is-projection]; and its engine face — the projector emits the whole document from the warrant set, populated sections and empty ones alike [@projector-emits]; two commands do the work — PROJECT makes the document and GATE verifies it: the exact projection passes, hand-edited drift is rejected [@rm-cmds]; a capability MATRIX is owned as data with a named exception — which target affords which capability is a declared cell, and a cell that cannot be afforded reads TOOLCHAIN-EXCEPTED rather than going silently absent, so an unsupported combination is a disclosed fact rather than a gap a reader must infer from silence [@capability-owned-as-data]; a conversion PIPELINE is a coalgebra tracked as data — targets are OBJECTS and conversions are MORPHISMS in one declared adjacency, so a route is a WALK over declared edges rather than a script someone runs by hand, and a route naming an edge the adjacency does not declare is refused instead of discovered at run time [@pipeline-is-a-coalgebra]; EVERY derived artifact is regenerated and compared, never trusted — the generalisation of the prose drift face to every projection a project commits, so a table, a manifest or a figure that has drifted from the source it is derived from fails the gate exactly as drifted prose does; a committed derivative nothing regenerates is an assertion about the past [@derived-is-regenerated-not-trusted]; the paper's drift face imports this same certificate — the gate rejects any prose that has drifted from its projection [@gate-rejects-drift].

## Cotype: Gating the Reasoning, Not Only the Claims

A printed conclusion must be backed by an assertion that would fail if it were false — the check apparatus covers landed claims, each carrying a command, while printed reasoning carries nothing, so a conclusion can sit beside output from the same run that refutes it and no gate notices [@conclusion-backed], and the gate is deliberately weak in one direction and strong in the other — it cannot tell whether an assertion is the RIGHT one, only that a conclusion was staked with nothing behind it, because a gate that judged relevance would have to be right about meaning and would fail open when it was not [@conclusion-weak-direction]. A label is a point in an orbit — it names a concept from the carrier one was standing in, so a concept has one identity and many labels, and a foreign corpus splits into what to REUSE, where an existing witness family already covers the idea and the term becomes another argument to it, and what to WEDGE [@label-carrier].
