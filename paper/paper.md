# Paperkit: A Paper Is a Projection of a Verified Claim-DAG

*A self-hosting document toolkit — this paper is projected and gated by the tool it describes.*

## 1. The Problem: Papers Assert, Nothing Checks

Paperkit treats a scholarly paper as the projection of a claim-DAG [@paper-is-projection][^paper-is-projection] — each node a single claim [@node-is-claim], each claim carrying a machine-checkable verifier [@claim-bears-check]; and a claim whose verifier fails simply does not appear in the prose [@fail-omits] (developed below at [@gate-rejects-drift]).

## 2. The Model: A Paper as a Projected Claim-DAG

A claim is a single record — a statement, the rubric section it belongs to, its dependencies, and its verifier [@claim-is-record] (grounded above in [@claim-bears-check]) — which is exactly the shape of a bibliography entry [@record-is-bibentry]. The prose is projected, not authored [@prose-projected] (developed below at [@ordered-by-deps], [@joined-by-glue]): within each section the claims are ordered by their dependency edges [@ordered-by-deps] (developed below at [@projector-emits]) and joined by connective glue [@joined-by-glue] (developed below at [@projector-emits]), the same warrant set always giving the same document [@deterministic] (grounded above in [@ordered-by-deps]).

## 3. The Dependency Graphs: Prose Order, Grounding, and the Typed Move

A claim's from-edges fix its place in the prose — the projector emits a claim only after the claims it lists, so document order is a topological sort of the from-graph [@edge-from-orders]. Rests-on is a separate grounding edge — a claim's effective grade is clamped to the weakest grade along it, $\mathrm{eff}(c) = \min\{\, \mathrm{grade}(c)\,\} \cup \{\, \mathrm{eff}(d) : d \in \mathrm{rests\text{-}on}(c)\,\}$, regardless of prose order [@edge-rests-grounds], and the two graphs are independent and often reversed: prose runs general to specific while grounding runs specific to general, so one pair of claims is at once a forward prose edge and a backward grounding edge [@edge-chiral]. The move field names the typed rhetorical relation binding a claim to the prior beat — its kind decides its role (an entail move also grounds; turn, extend, parallel, and restate moves are prose only) and a section's declared scheme admits only certain move-kinds [@edge-move-types]. The grounding relations gather into a table of their own formulas, itself a projection of the claim-DAG — the clamp, the disjointness the measurement reads, the sensitivity increment and its collapse, GENERATED from the very claims that state them so the table cannot drift, and carried into the rendered document as native, accessible Office Math, so the paper both states these relations and demonstrates that equations survive the render intact, in a table cell [@edge-formulas].

## 4. The Engine: Projection and Gate

The projector emits the whole document from the warrant set [@projector-emits], so the committed prose is a build artifact, not a source any hand should edit [@prose-is-artifact] (grounded above in [@prose-projected]). The gate rejects any prose that has drifted from its projection [@gate-rejects-drift], so a hand-edit cannot survive a build [@edit-cant-survive]. Coverage is enforced from both sides [@coverage-both-sides][^coverage-both-sides] — every required section must appear [@every-section-appears], and every claim tagged for a section must be cited within it [@every-claim-cited]. The engine is not a monolith but a handful of small single-responsibility modules — a resolver that runs a check, a grader that sweeps it for sensitivity, a grade ladder that interprets the sweep, a cache, a topology — each importable and tested on its own, so a change to one carries a small blast radius [@module-split].

## 5. The Check-Resolver: One Pluggable Seam

A claim's verifier is named type:target [@verifier-named], and the gate dispatches it through a small registry of check types [@gate-dispatches], so supporting a new domain means adding verifiers, not editing the engine [@new-domain-adds]. A verifier ships built in per verb [@two-builtins][^two-builtins] — file, that an artifact EXISTS [@file-builtin], cmd, that a script EXECS green [@cmd-builtin], result, that a sibling project's gate verdict PARSES green — the verb that lets one project rest on another it does not re-derive [@result-builtin], and agree, that N independent producers CONCUR — all exit green and emit identical output, the verb that corroborates a fact across implementations rather than trusting one (Δ·agree) [@agree-builtin]; and cmd is the universal escape hatch every other check reduces to [@cmd-escape] (grounded above in [@cmd-builtin], [@new-domain-adds]). Pointed at a dataset the project SHIPS rather than a transient command, that hatch turns a claim's evidence into a versioned artifact — a captured snapshot, a generated figure — that anyone can re-read and a single edit can falsify [@dataset-backed] (grounded above in [@new-domain-adds]), kept honest because the verifier re-runs the producer that built that dataset and fails on drift — shipped evidence that is fresh by construction, not a figure pasted in once and quietly gone stale [@dataset-fresh]. The fifth verb IMPORTS rather than runs — concept resolves a key against a LIBRARY that authored and graded that witness once, and the citing view gets its CERTIFICATE (the verdict, and the engine fingerprint the grade was measured against) instead of re-executing a proof [@concept-builtin][^concept-builtin], and a library is a hash-cons table, not a cache of repeats — every concept interns to exactly ONE canonical node and a view holds a reference, so the test for lifting something into it is whether it IS a concept, never whether it has been written down twice [@concept-interned], which is what lets one truth carry SEVERAL prose faces — a pitch, a deep exposition and a tutorial may each say a concept in their own register while importing the identical proof, so the faces cannot drift apart and a view may add no witness code at all [@concept-views]. And a library is shareable because the seam resolves CONSUMER-FIRST — a project's own library answers a key if it has one, and only otherwise does the engine's, with the fallthrough decided PER KEY rather than per directory, so a downstream repository may keep its own concepts without eclipsing the engine's and may cite an engine concept where that is the honest import [@concept-shareable][^concept-shareable]. Resolving a key to its witness is itself GRADED — a key is family/subfamily/argument, walked by one depth-agnostic loop, so a parameter axis costs no copy per argument: two keys may share ONE implementation and still read as distinct witnesses, because --without-K decides distinctness at KEY granularity [@key-graded][^key-graded]. Interning to one canonical node does not erase the names a concept was coined under — a label is a point in an orbit, naming the concept FROM a carrier, so the index maps concept to carrier-to-label and a reader meets the concept under the name their own field uses [@label-orbit][^label-orbit]. A verdict is reusable exactly when nothing it REACHED has changed — the cache keys on the slice a check can reach, its witness plus the transitive closure of the module-level names that witness references and the files those live in, so an edit invalidates what touched it rather than the whole module [@cache-slice][^cache-slice]. A PRINTED conclusion must be backed by an ASSERTION — the apparatus covers landed claims, so an analysis script may print a conclusion beside output from the same run that refutes it and nothing notices, because the conclusion was never a claim [@conclusion-gated][^conclusion-gated], and the gate is deliberately one-directional — it can force a conclusion to be backed, but not force the backing assertion to be the RIGHT one, so it closes the unbacked-conclusion set and leaves the wrong-assertion set to review [@conclusion-direction].

## 6. Self-Hosting: This Paper Verifies Itself

This paper is itself a paperkit project [@paper-is-paperkit] (grounded above in [@paper-is-projection]) — its claims are these warrants [@claims-are-warrants] (grounded above in [@record-is-bibentry]), its prose is their projection [@prose-is-projection] (grounded above in [@paper-is-paperkit]), and the gate that accepts it is the very subject it describes [@gate-is-subject] (grounded above in [@paper-is-paperkit]). The verifiers behind this section run paperkit on paperkit — projecting a fixture, drifting it, and confirming the gate rejects the drift [@paperkit-on-paperkit] (grounded above in [@prose-is-projection]), so the document's correctness and the tool's are one green check [@one-green-check].

## 7. The Projector: Weave, Connectors, and Placement

Within a section the projector weaves the claims into one paragraph rather than a list — the first clause is capitalized, each carries its own citation tag, and the rest attach inline [@weave-sentence]. Adjacent clauses are joined by a connector resolved in priority order — an explicit join wins, else the typed move supplies its default connector, else a legacy glue [@connector-resolution]. A warrant that names an emit asset is placed verbatim rather than woven — fenced by the language its extension implies, or rendered as a markdown image when the asset is one [@emit-placement]. Projection structure is configured, not hard-coded — the numbered flag toggles section numbers and the references flag toggles the bibliography heading [@config-flags], and claim text is normalized on the way out — a triple dash becomes an em dash, an inter-word double dash an en dash, LaTeX escapes resolve, braces strip, and a trailing period drops [@latex-clean].

## 8. The Gate: Resolution and Its Strict Modes

RESOLVE is the gate's second invariant — a cited claim whose check fails blocks the gate, so the verdict is the conjunction of every cited claim's check [@resolve-passes]. An uncited placement — a block the document carries but no prose cites — is a postulate: advised against by default and rejected under --safe, the zero-postulate mode [@safe-rejects-postulates]. Because the gate reduces each check to a boolean it cannot tell two cited claims that share one witness apart (proof-irrelevance, Axiom K) — so --without-K forbids the collapse, demanding a distinct witness per claim [@without-k-distinct]. The gate resolves a project's distinct checks concurrently (the bib is its makefile), and the verdict is independent of the worker count — parallel equals serial [@jobs-parallel].

## 9. Adequacy: How Δ Grades a Check

A passing check only proves a sentence named a verifier, not that the verifier entails it — so Δ grades each check on a ladder by how much it can fail: a presupposed file is vacuous, a contingent one existence, and a content-sensitive command behavioral [@grade-ladder].

- The grade is empirical, not declared — Δ corrupts each input in turn and watches whether the check flips from pass to fail, and the inputs whose corruption flips it are its sensitivity set [@mutation-probes].
- A grade is a pure function of the content a check reads, so it is cached PER CHECK on that read footprint — the files the check opens — over a shared engine epoch, and the expensive mutation sweep reruns only for the checks a change actually touches; the whole-project content key is the coarse soundness basis the per-check key refines [@content-cache].
- The sweep runs in a sandbox copy whose mutation surface excludes sibling projects (a nested directory with its own paper.toml), so each project grades independently of the others [@sandbox-grade].

--min-strength turns the grades into a gate — a project fails if any cited claim's check grades below the threshold, which is how this paper enforces its own proof-relevance in CI [@min-strength]. Δ traces each check's READ footprint — the project files it opens when it runs, a superset of its sensitivity set — and beyond keying the per-check cache, that footprint SCOPES the sweep: each check is graded against the files it reads, never the whole repository [@footprint-scopes]. One grade sits outside the falsifiability ladder: a verdict-import is graded imported — its adequacy delegated to a sibling project the gate verifies on its own, run once and never mutation-swept — the way one paper rests on another it does not re-derive [@imported-grade].

## 10. Liveness: Resumable Witnesses

A slow but sound check need not block — it is structured as a pump/parse witness, where pump advances opaque state one increment with no verdict and parse reads the meaning (done, progress), and the driver only ever loads, pumps, serializes, and persists [@pump-parse-witness]. Under a budget the driver stops after an increment and persists the resumption token, exiting with a resume code rather than a failure — so a slow witness reads as resume me, not as a falsified claim, and resuming completes exactly the run an uninterrupted one would [@resumable], on the strength of a single soundness obligation — that deserializing a serialized state returns that same state — which the driver asserts on every run, so a witness whose token loses information is rejected outright [@roundtrip-obligation].

## 11. Rhetoric: Typed Moves and Checkable Schemes

The layer that attaches one clause to the next is not glue but prosody — a typed move whose kind (entail, extend, turn, parallel, restate) and default connector form a data-driven vocabulary, so a new rhetorical device is a new row, not new code [@prosody]. A section may declare a scheme that constrains its claim count — a period is one balanced beat, a distich two, a tricolon exactly three, while an enumeration or a ladder takes two or more [@scheme-count]. Schemes are opt-in: a scheme lives in the rubric's third column and only a section that declares one is checked, so existing prose is never retroactively constrained [@scheme-opt-in], and so form becomes checkable the way the claim-DAG made content checkable — a declared section whose realized moves break its scheme fails the rhetoric gate, so intentional use of language stops being prose you hope for and becomes structure you specify and verify [@form-gate].

## 12. The Repository: A Family of Verified Projects

The engine is domain-free, so the repository is several paperkit projects at once — each a directory with a paper.toml that projects its own document — discovered by that file, never hard-coded [@multi-project]. The projects form a dependency DAG over the shared engine: the paper and the tool boundaries rest on the engine alone, while the README's gate runs the paper's and the report ingests the paper's machine-readable grades [@project-dag]. A pre-commit githook is the local CI — every commit runs bazel test //:hook, the single Bazel target that gates every document (each claim a per-claim check target plus the project invariants, --safe --without-K) and grades it behaviorally adequate (Delta --min-strength); and because that target gates the WORKING TREE while a commit lands the INDEX, the hook first verifies they agree on every gated path, so the verdict it renders is the verdict the commit carries and the repository is never committed in a broken state; and a footprint audit alongside it confirms every claim's declared reads cover the inputs its check actually opens (Ξ·dag·reads), so an under-declared staging dependency is named with its remediation rather than surfacing later as a cryptic missing file [@local-ci]. Every engine tool ships its behavioral boundaries as a ⟨P, F, δ⟩ suite, and those suites are themselves gathered into a gated project that projects to BOUNDARIES.md [@boundaries-project], and the verification report is a fourth project whose figures are live pipeline output — rendered from the gate and Δ --json data, never scraped — so a stale report fails its own freshness gate [@report-live]. A project rests on another through exactly two imports — a VERDICT import takes a sibling's whole gate result, a CERTIFICATE import takes one concept its library graded — and both cross a project boundary, which the engine's verb registry marks as a structural property rather than leaving to convention [@compose-two-imports], and both DELEGATE their adequacy to the owner instead of re-deriving it — the importing side does not sweep the proof it imported, because the owner already graded it and grading it again would measure the same thing twice while claiming independence [@compose-delegates], which is the point: the alternative was measured and refused — re-deriving a sibling's proof in the citing view costs the whole grid again for an answer the owner already holds, and worse, produces a SECOND result that can disagree with the first, so composition is dispatch on ownership rather than recomputation [@compose-refuses-regrid]. And the imports CHAIN — a project may rest on a sibling that itself rests on a third, so a verdict carries the whole cone beneath it and the family of projects is one claim-DAG at a coarser grain, the same relation between claims holding between the documents that contain them [@compose-chains][^compose-chains].

## 13. Implications: What Follows, and the Honest Limits

Because the document IS the projection, regenerating it is idempotent and any hand-edit is rejected — the prose cannot drift from its claims, so what you read is always what was checked [@fresh-by-construction]. But a passing check only proves a sentence NAMED a verifier, not that the verifier ENTAILS the claim — a false sentence with a behavioral yet irrelevant check still passes the gate, so verification here is adequacy, not proof of meaning [@adequacy-gap]. Δ flags this gap without yet closing it: a check can grade behavioral while sensitive only to inputs other than the document's content, and content-sensitivity marks the difference — so behavioral is necessary but not sufficient for relevance [@crash-sensitive-limit]. A check is arbitrary code — cmd is the universal escape hatch every check reduces to — so gating a document EXECUTES its checks: the warrant set is trusted code, like a makefile, and verifying an untrusted document would be running it [@trust-boundary], so a check runs in a controlled, default-deny environment after sshd's defence against injection — no inherited LD_PRELOAD, IFS, or BASH_ENV — so a verdict cannot be injected through the caller's environment, though which tools the PATH resolves remains the host's, leaving reproducibility resting on the host toolchain [@env-sanitized]. That residual is a trust surface, not only a reproducibility one: a check runs through a shell that resolves tools by name, so paperkit drops PATH's relative and empty entries — the ones that would resolve to the very project directory being gated — closing the shadow where a document plants a tool beside itself; which absolute directory resolves a tool it keeps, the host's own trust, the same as the toolchain's [@path-surface]. Definition resolution turns each claim's sensitivity into a distinct engine-capability fingerprint, and the coherence grade checks declared grounding against it — a rests-on edge whose fingerprint is disjoint from its premise's, $\mathrm{fp}(c) \cap \mathrm{fp}(d) = \emptyset$ for $d \in \mathrm{rests\text{-}on}(c)$, is grounding the measurement cannot see, narrowing the relevance gap by measurement rather than leaving it asserted [@grounding-reflected][^grounding-reflected]; and stricter, emergence is the coverage sibling of that overlap check — grounding asks whether a rests-on edge overlaps its premise's fingerprint, emergence whether a claim's whole fingerprint is covered by its premises', so a claim that adds no engine sensitivity beyond its grounding COLLAPSES, its witness emerging by consuming them, while any residual $\mathrm{incr}(c) = \mathrm{fp}(c) \setminus \bigcup_{d \in \mathrm{rests\text{-}on}(c)} \mathrm{fp}(d)$ is the claim's irreducible increment, and the claim collapses exactly when $\mathrm{incr}(c) = \emptyset$ [@emergence-collapse], and that verdict is sound for DELETION — replacing a collapsed claim's witness with consumption of its premises loses none of the proof's discrimination, because every input that flips the claim flips a premise too (its fingerprint is covered), so the premise's witness fails and blocks it; an increment's residual is precisely the input no premise catches, so collapse is safe to delete and increment is a keep-warning [@collapse-safe]. The same declared-vs-measured comparison runs one level UP, on the document's own SECTIONS — the authored grouping $\sigma$ is checked against the partition $P^* = \arg\max_P [Q_E(P) - \gamma \cdot d(P, \sigma)]$ that rests-on modularity derives, and the residual $d(\sigma, P^*)$ NAMES the claims whose grounding lives outside their section rather than scoring the grouping [@grouping-residual][^grouping-residual], and the ungrounded tail falls back to $\sigma$ BY CONSTRUCTION rather than by a special case — modularity's null term cancels a lone edge's chance-expectation, so a sparsely-connected region is argmax-indifferent and the $\gamma$ term decides there [@grouping-tail-falls-back]; and a named claim carrying a `link` is DISCHARGED, as the structure and grounding faces discharge theirs, so the raw residual stays the measurement while the un-acknowledged count is what an explicit budget gates — without that split a threshold would red on the deliberate forward references a thesis makes, measuring the wrong thing while looking rigorous [@grouping-discharge] (grounded above in [@grouping-residual]). And grouping is not PAGINATION — what coheres is structural and emergent, where a unit BREAKS is a rhetoric choice on top, so the same cluster may render as one staged unit, as a unit per claim, or as a summary line [@grouping-not-pagination] (developed below at [@genre-registry]), which makes the second axis a named objective, REGISTERED rather than enumerated — the built-in objectives are data in one engine module and a project declares its own in paper.toml exactly as it declares a check type, so a consumer adds a pagination objective without touching the engine [@genre-registry]; and because an OPEN set cannot be gated by exhaustive case analysis, what is gated is the SEAM — an objective must be a real function of the grouping (every claim lands in exactly one unit, so a cut that drops or duplicates a claim is refused) and an unregistered name must REFUSE rather than fall back to a default, since a silent fallback would paginate a document under a genre nobody asked for [@genre-gates-the-seam]. A BUDGETED objective shows why the axis needed to be its own — the unbudgeted cluster cut leaves this paper's largest section on one unit while a per-claim cut gives a four-word claim its own, so the talk objective keeps the grouping's bracketing and splits only over-full clusters, always at a CLAIM boundary, leaving a single over-long claim its own unit rather than inventing a boundary the document does not have [@genre-budget] (grounded above in [@genre-registry]), and a second registered objective proves the axis is genuinely OPEN rather than two-valued — the collection cut MERGES where the talk cut splits, since its cost is the cross-unit grounding edge (a unit resting on a claim outside itself is not self-contained), so it closes the grounding graph transitively into standalone subtrees; a closed enumeration built around splitting would have had no room for an objective running the other direction [@genre-collection] (grounded above in [@genre-registry]). So the projector gains a SECOND observation shape rather than a fifth target — project linearizes the DAG to one flat stream that every citation target materializes differently, while observe SEGMENTS it into bounded units indexed by target AND genre, which cannot be a branch inside a function returning a string; it returns the units themselves, not rendered prose, since re-linearizing there would undo the segmentation it exists to perform [@observe-second-shape][^observe-second-shape], and the units it cuts are grouped by the GROUNDING-derived partition rather than the authored sections, at the resolution the genre asks for — and ONE owner computes that partition for both consumers, since the projector cutting a deck on it and the $\partial^2$ grade measuring its distance from $\sigma$ sit on opposite sides of the component lattice; a second copy would drift, and the grade would then be measuring a grouping no deck uses [@observe-regroups-on-grounding] (grounded above in [@grouping-residual]), where $\gamma$ controls the group COUNT and not merely which claims group together — a relabelling sweep alone can never create or merge a group, so the derived partition would always carry $\sigma$'s cardinality and the resolution knob would move labels while leaving the structure fixed; adding the MERGE of two GROUNDED-adjacent groups is the operator that makes $\gamma \to \infty$ recover the authored sections and $\gamma \to 0$ recover the modularity optimum, and restricting it to adjacency is what stops a document being fused on no evidence [@partition-merges], and that resolution is REACHABLE rather than frozen into each genre — $\gamma$ is the deck-analog of the adequacy floor, so a document may be re-cut coarser or finer without inventing a genre to carry the value; an explicit setting overrides the genre's own while its absence leaves the genre's declared resolution meaningful, which an engine-wide default would have destroyed [@gamma-is-reachable]. And a project-declared objective RUNS, so the open half is open in fact and not only in principle — a consumer registering an objective it could not invoke would have a registry entry and no pagination; the engine runs the declared command on the `cmd:` model, groups in and units out, and holds the result to the SAME totality invariant a built-in meets, since what a pagination IS does not depend on who wrote it [@genre-declared-runs] (grounded above in [@genre-gates-the-seam]), and its cut is bounded by what authors DECLARE, not by the mechanism — a grouping reads only the grounding a project actually states, so where rests-on is dense the segmentation carries argument structure and where only prose order is declared it reduces to the section cut a flat render already gives; the honest form of the feature therefore reports which case a document is in rather than presenting the second as though it were the first [@observe-bounded-by-adoption] (grounded above in [@observe-second-shape]). The structure residual closes by PROJECTION rather than collapse — a grounding edge that runs beyond prose adjacency now renders as a transitively-reduced cross-reference, making the grounding DAG visible in the prose and not only in the metadata; its richer materializations, an expounding clause or a figure beyond the bare citation, are the open rhetorical work [@forward-direction].

## 14. Related Work

Literate programming interleaves a program with the prose that explains it, so code and explanation are kept in one source and cannot drift apart [@knuth-lit]; in a parallel spirit, reproducible-research practice ships the code and data that regenerate every figure and number, so a published result can be re-run rather than trusted [@buckheit-donoho]; and on the engine side, build-systems theory frames a build as the demand-driven computation of verified targets from their dependencies — the same shape paperkit gives to a claim-DAG [@mokhov-build]; and from outside this repository, an independent consumer of this engine reports the limit of a freshness check — re-running the producer that built an artifact and comparing establishes DETERMINISM, not correctness — and the report separates its two halves honestly: the observation belongs to a reviewer in that project, who asked mid-implementation whether a generated table was undergoing the same claim rigor the prose would, while the confirming evidence is the project's own, where a generator was wrong twice (it read a label as a tier, and let an epilogue's exit status leak into a claim that never sets one) and the freshness check passed cleanly through both, because it only ever compared the committed copy against what that same generator had just emitted — so a SECOND, independent oracle catches what a self-comparison structurally cannot, which is this paper's agreement argument reached from the outside [@cassian-fresh].

## 15. Conclusion

By making every claim a verifier and the document their projection, paperkit closes the gap between what a paper says and what has been checked [@closes-gap] (grounded above in [@one-green-check]): an unverified sentence cannot ship [@unverified-cant-ship], because it does not project [@not-project] (grounded above in [@fail-omits]).
